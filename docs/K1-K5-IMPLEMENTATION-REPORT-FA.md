# گزارش اجرای K1 تا K5

مبنا: `docs/01-KANBAN-AGENT-IMPLEMENTATION-FA.md` و کد جاری مخزن. این گزارش نتیجهٔ اجرای محلی این مرحله است؛ گزارش‌های قدیمی جای نتیجهٔ این اجرا استفاده نشده‌اند.

## نتیجهٔ بررسی

| بررسی | نتیجه |
|---|---|
| مجموعهٔ کامل PHP | موفق؛ ۲۶۴ آزمون، ۹۹۸ بررسی، بدون شکست، خطا یا skip |
| مجموعهٔ کامل مرورگر | موفق؛ ۲۱ آزمون Edge، شامل Reverb واقعی، چند کاربر و برد، لمس و موبایل |
| سناریوهای سازمانی KNB101–150 | ۵۰ از ۵۰، استخراج مجدد از گزارش‌های همین اجرا |
| Composer | اعتبارسنجی سخت ساختار و وابستگی‌ها موفق |
| دارایی‌ها | ساخت CSS و JavaScript موفق |
| فاصله‌های diff | بدون خطای whitespace |

Baseline ابتدا ۲۵۱ آزمون و ۴ شکست داشت. شکست‌ها انتظار نمایش قدیمی «بارگذاری‌شده/کل» بودند؛ نمایش قبلاً به درخواست کاربر به «کل» یا «کل/ظرفیت» تغییر کرده بود. آزمون‌های قدیمی حذف نشدند؛ انتظار آن‌ها با بررسی دقیق متن شمارندهٔ همان ستون اصلاح شد.

## خروجی هر فاز

| فاز | نتیجهٔ اجرا |
|---|---|
| K1 | قراردادهای موجود Trait، رجیستری و منابع ممیزی و حفظ شدند. مسیر Provider/Handler قدیمی همچنان از آزمون‌ها عبور می‌کند؛ منبع خالی و منبع خارج از allowlist دسترسی اضافه نمی‌کنند. |
| K2 | Provider و عملیات موجود با آزمون‌های محدوده، cursor، نگاشت، نسخه، جلوگیری از اجرای تکراری و رقابت دو پردازش WIP بررسی شدند. آزمون رابطه‌ها به صفحهٔ ۱۰۰ کارتی گسترش یافت. |
| K3 | قرارداد اختیاری `CardDetailsProvider`، دادهٔ تایپ‌شدهٔ بخش و فرمان عمل افزوده شد. بارگذاری مستقل و صفحه‌ای، مجوز مستقل بخش‌ها، لغو دسترسی، حذف کارت، پیوند امن و قالب سفارشی ثبت‌شدهٔ سرور پوشش دارند. |
| K4 | Drawer و Modal محتوای پایه و دکمه‌های مشترک دارند. Drawer عرض قابل تنظیم، هدر/پایین ثابت، محتوای اسکرول‌شونده، نمایش تمام‌صفحهٔ موبایل، مهار فوکوس و قفل اسکرول پس‌زمینه دارد. Board و List همان مسیر جزئیات را باز می‌کنند. |
| K5 | آزمون‌ها، راهنماهای مصرف‌کننده، نمونه‌های CRM/Order/Ticket، گزارش سناریوها، تصاویر و ZIP بازبینی تهیه شدند. |

## APIهای افزوده‌شده

- `Contracts/CardDetailsProvider`: توصیف سبک بخش‌ها، بارگذاری یک صفحه و اجرای عمل دامنه با `ActionResult`.
- `Data/CardDetailSectionData`: کلید، عنوان، ترتیب، وضعیت، خلاصه، دادهٔ محدود، cursor، قابلیت‌ها و عمل‌های مجاز؛ همهٔ متن‌ها escape می‌شوند.
- `Data/CardDetailAction`: payload محدود، شناسهٔ عملیات و نسخهٔ مورد انتظار.
- `BoardBuilder::detailsProvider()` و `detailSectionView()`: ثبت کلاس و قالب فقط از کد معتبر میزبان.
- `DisplaySettings::drawerWidth` و `views.drawer_width`: پیش‌فرض ۵۶۰، بازهٔ ۳۲۰ تا ۹۶۰ پیکسل؛ تمام‌صفحه در موبایل.
- `BoardDefinition` فقط پارامترهای اختیاری انتهایی گرفت؛ متد اجباری به `DataProvider` یا `ActionHandler` اضافه نشد.

## امنیت و مالکیت دامنه

شناسهٔ کارت باز و صفحات/شناسه‌های عملیات بخش‌ها در Livewire قفل‌اند. هر درخواست، کارت و توصیف بخش را دوباره در محدودهٔ Provider می‌خواند. مجوز مشاهدهٔ کارت، مجوز نظرها یا پیوست‌ها محسوب نمی‌شود. غیرفعال‌کردن details/custom actions با فراخوانی مستقیم قابل دورزدن نیست. خطای نامشخص موفق اعلام نمی‌شود و شناسهٔ عملیات برای تلاش مجدد حفظ می‌شود.

Provider میزبان همچنان باید query، مجوز هر بخش، تراکنش، نسخه و اجرای تکراریِ عملیات دامنه را خودش کنترل کند. قرارداد آمادهٔ Subtasks، Dependency، Checklist، Comments/Activity، Attachment، Related و Custom بخش‌ها مالک جدول یا مدل تجاری نمی‌شود. فرم سفارشی میزبان مسئول پیش‌نویس و هشدار خروج خودش است؛ بخش‌های عمومی فاقد فرم و دادهٔ جعلی‌اند.

## کارایی

در آزمون ۱۰ ستون و ۱۰۰هزار ردیف، ۲۵۰ کارت نمایش و ۲۶۰ مدل ساخته شد؛ تعداد query برابر ۲۱ بود. صفحهٔ ۱۰۰ کارتی با رابطهٔ صاحب، ۳ query داشت. زمان و حافظهٔ واقعی همان اجرا در `ENTERPRISE-BENCHMARK.json` ثبت شده است. این عددها تضمین زمان پاسخ محیط تولید نیستند.

## تصاویر و مستندات

تصاویر تازه در `docs/redesign/k1k5/` قرار دارند: Board، List و Drawer در حالت روشن، تاریک، راست‌به‌چپ و موبایل. تصویر Drawer موبایل به‌صورت بصری بازبینی شد. راهنماهای `USAGE.md`، `CONFIGURATION.md`، `SOURCES.md`، `DRAWER.md`، `EXAMPLES-CRM-ORDERS-TICKETS.md`، `UPGRADE.md` و `TEST-SCENARIOS.md` نقطهٔ شروع مصرف‌کننده‌اند.

فهرست فایل‌های این مرحله در `K1-K5-CHANGED-FILES.json` و شواهد قابل پردازش در `K1-K5-RESULTS.json` است. مخزن از ابتدا تغییرات ثبت‌نشده داشت؛ آن‌ها حفظ شدند و ZIP وضعیت نهایی را برای بازبینی شامل می‌شود.

## حدود تأیید

اجرای این نوبت روی PHP 8.4.22، Windows، SQLite و Edge بود. MariaDB/PostgreSQL، مرورگرهای دیگر، CI خارجی و دستگاه واقعی موبایل در این نوبت دوباره اجرا نشدند. گزارش‌های قبلی آن‌ها به‌عنوان نتیجهٔ تازه معرفی نمی‌شوند. ZIP برای بازبینی است و این گزارش تأیید استقرار تولید نیست.

Task Manager ساخته نشد و Calendar تغییر نکرد؛ هیچ migration تجاری اجباری به هسته افزوده نشد.
