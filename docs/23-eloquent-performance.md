# واکشی، صفحه‌بندی و اندازه‌گیری

کوئری خواندن از `visibleQuery()` آغاز می‌شود؛ سپس وضعیت قابل مشاهده، بایگانی، فیلتر و جست‌وجو اعمال می‌شوند. شمارنده‌ها در پایگاه داده اجرا می‌شوند و به تعداد کارت‌های صفحه وابسته نیستند.

```php
->fields(['rank' => 'sort_rank', 'dueAt' => 'due_at'])
->filters(['priority', 'dueFrom' => 'due_at', 'dueTo' => 'due_at'])
->sorts(['manualOrder', 'dueAt', 'title'])
->with(['assignee:id,name'])
->select(['id', 'title', 'status', 'assignee_id', 'sort_rank', 'due_at'])
```

شناسه و فیلدهای نگاشت‌شده به select افزوده می‌شوند؛ کلید خارجی رابطه را صریحاً انتخاب کنید. نمایش محاسباتی فقط روی رکوردهای صفحه اجرا می‌شود. فیلتر و مرتب‌سازی، نام ستون دلخواه از کاربر نمی‌پذیرند.

صفحه‌بندی بر اساس مقدار مرتب‌سازی و شناسه پایدار است؛ null در صعودی اول و در نزولی آخر است. برد مختلط از هر منبع حداکثر `pageSize + 1` رکورد می‌خواند و با موقعیت جداگانه منابع ادغام می‌کند؛ حافظه متناسب با تعداد منابع انتخاب‌شده است. ترتیب عنوان/اولویت و شناسه متنی در SQL و ادغام PHP باینری یکسان است؛ عبارت مناسب SQLite/MySQL/PostgreSQL انتخاب می‌شود. برای ترتیب زبانی اختصاصی، Provider میزبان لازم است. ترتیب متنی در آزمون واقعی SQLite، MariaDB 11.8.2 و PostgreSQL 18.4 تأیید شده است.

نشانگر صفحه با رمزنگاری احرازشده لاراول از دستکاری محافظت می‌شود؛ به برد، کاربر، محدوده، منابع، ستون، جست‌وجو، فیلتر، ترتیب و اندازه صفحه وابسته است. انقضا یا تغییر کوئری، نشانگر قدیمی را رد می‌کند. عمر پیش‌فرض ۳۶۰۰ ثانیه است. `APP_KEY` باید بین workerها یکسان و محرمانه باشد.

```sh
# PowerShell؛ نوشتن گزارش اندازه‌گیری محلی
$env:KANBAN_WRITE_BENCHMARK='1'
php vendor/bin/phpunit --no-coverage tests/Performance/EnterpriseQueryPerformanceTest.php
```

گزارش واقعی در `.phpunit.cache/enterprise-benchmark.json` در ریشه مخزن است؛ ۱۰ ستون، داده 10k/100k، ۲۵۰ کارت نمایش و ۲۶۰ رکورد خوانده‌شده با ۲۱ query. اعداد زمانی وابسته به همین محیط Windows/SQLite هستند. حد زمانی تولید ادعا نمی‌شود؛ CI فقط بودجه تعداد query و رکورد را کنترل می‌کند.

ایندکس میزبان پیشنهادی: `(scope, status, rank, id)` متناسب با شروط واقعی. پکیج ایندکس اجباری ندارد. جست‌وجوی LIKE برای جست‌وجوی متن بزرگ جایگزین موتور جست‌وجو یا full-text بهینه نیست.

کش شمارش/آمار اختیاری و پیش‌فرض خاموش است. کلید شامل هویت، برد، منابع، متن SQL و ورودی‌های visibility، کوئری و نسخه محدوده است. عملیات عمومی پکیج بعد از commit آن را باطل می‌کند. تغییر مستقیم مدل یا مجوز در میزبان نیز باید `ModelQueryCache::invalidate($context)` را صدا بزند؛ در غیر این صورت کش را خاموش نگه دارید.
