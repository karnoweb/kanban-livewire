# برد چندمنبعی و جداسازی دسترسی

ثبت منبع، مجوز منبع در برد و فیلتر رابط سه مفهوم مستقل‌اند. نمونه اجرایی: `workbench/app/Kanban/EloquentBoardFactory.php` و صفحه `/models/mixed`.

```php
->sources(['tasks', 'tickets'])
->stageMap([
    'tasks' => ['todo' => 'todo', 'doing' => 'doing', 'done' => 'done'],
    'tickets' => ['open' => 'todo', 'answering' => 'doing', 'closed' => 'done'],
])
```

تمام مراحل هر مدل باید نگاشت داشته باشند؛ ترکیب بدون نگاشت رد می‌شود. نگاشت چند مرحله یک مدل به یک ستون برای خواندن مجاز است، ولی انتقال معکوس مبهم رد می‌شود. شناسه‌ها `tasks:17` و `tickets:17` هستند؛ شناسه خام و منبع ناشناخته رد می‌شوند.

```php
$query = new \Karnoweb\Kanban\Data\BoardQuery(filters: ['source' => ['tasks']]);
```

این فیلتر تنها بین منابع مجاز برد انتخاب می‌کند. منبع خارج از برد باعث خطا می‌شود؛ هیچ query روی آن اجرا نمی‌شود. ثبت منبع جدید، منابع بردهای قبلی را افزایش نمی‌دهد.

برای API یا داده غیردیتابیسی، `KanbanModelRegistry::registerProvider()` و `provider()`/`handler()` صریح برد را استفاده کنید. ترکیب داده غیردیتابیسی با مدل نیازمند Provider ترکیبی میزبان است؛ انتخاب خودکار مدل‌ها هرگز چنین منبعی را به Eloquent تبدیل نمی‌کند. Provider میزبان مسئول اجرای همان فهرست منابع مجاز است.

مرتب‌سازی دستی بین منابع با راهبرد پیش‌فرض غیرفعال است. میزبان می‌تواند `RankStrategy` مشترک بدهد که `supports()` را برای آن برد تأیید کند. انتقال وضعیت در برد مختلط همچنان ممکن است؛ anchors بدون ذخیره مشترک، ترتیب بین منابع را فعال نمی‌کنند.

عملیات گروهی اتمی بین چند اتصال پایگاه داده، نیازمند handler دامنه است؛ handler عمومی برای یک اتصال، تراکنش همه یا هیچ و برای چند اتصال، رد روشن ارائه می‌کند.
