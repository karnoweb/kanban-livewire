# گردش‌کار، نسخه و رتبه

مراحل می‌توانند آرایه ثابت یا نام BackedEnum (شمارش با مقدار ذخیره‌شدنی) باشند. اگر `stages()` داده نشده باشد، cast مربوط به فیلد وضعیت بررسی می‌شود. متدهای اختیاری Enum شامل `label`, `color`, `order`, `wipLimit`, `allowedTransitions` هستند.

```php
->fields(['stage' => 'status', 'rank' => 'sort_rank', 'version' => 'version', 'archivedAt' => 'archived_at'])
->stages(['todo' => 'To do', 'doing' => ['title' => 'Doing', 'wipLimit' => 3], 'done' => 'Done'])
->transitions(['todo' => ['doing'], 'doing' => ['todo', 'done']])
```

مجوز مدل و سیاست انتقال برد هر دو باید اجازه بدهند. قبل از نوشتن، ردیف در محدوده مجاز دوباره خوانده و قفل می‌شود. اگر version نگاشت شده باشد، `expectedVersion` برای تمام تغییرات ردیف لازم است؛ فقدان/کهنگی آن تعارض می‌دهد. نسخه پیش‌فرض عمومی عدد افزایشی است؛ مدل با نسخه دامنه‌ای متفاوت handler اختصاصی می‌دهد.

```php
->action('approve', function ($record, $command, $context): void {
    app(\App\Services\ApproveTask::class)->handle($record, $command->payload['formData']['note']);
}, ['note' => ['required', 'string', 'max:500']])
```

نام عملیات باید از قبل تعریف شده باشد. اجرای نام متد خام کاربر مجاز نیست. `authorize()` برای این مثال باید `action:approve` را هم کنترل کند. hookهای `validate`, `before`, `after` داخل تراکنش و `afterCommit` پس از ثبت هستند. رویداد سرور `KanbanModelChanged` برای audit/broadcast میزبان منتشر می‌شود؛ جدول لاگ اجباری نیست.

راهبرد پیش‌فرض رتبه، عدد صحیح با فاصله ۱۰۲۴ است. جابه‌جایی معمول فقط یک ردیف را می‌نویسد؛ کمبود فاصله، حداکثر ۶۴ همسایه را بازتنظیم می‌کند. ناحیه بدون فضای کافی، تعارض روشن می‌دهد؛ بازنویسی همه ستون انجام نمی‌شود. `RankStrategy` قرارداد جایگزینی با رتبه کسری یا ذخیره مشترک منابع است. ستون رتبه اجباری نیست؛ بدون آن انتقال وضعیت مجاز ولی ترتیب دستی غیرفعال است.

قفل مشترک کش در سطح محدوده، عملیات پکیج را بین workerها سری می‌کند. ظرفیت سخت با شمارش تازه و بدون کش در تراکنش بررسی می‌شود. نویسنده‌های خارج از پکیج باید همان قواعد/قفل دامنه را رعایت کنند. تست دو پردازش SQLite برای آخرین ظرفیت در `tests/Integration/EnterpriseConcurrencyTest.php` است. خواندن، انتقال، نسخه، آمار، ترتیب متن، بازگشت تراکنش گروهی و ظرفیت روی MariaDB 11.8.2 و PostgreSQL 18.4 نیز آزمایش شده‌اند؛ رقابت چندپردازشی این دو موتور هنوز اندازه‌گیری نشده است.

جلوگیری از اجرای تکراری به cache مشترک ماندگار نیاز دارد؛ `array` برای تولید مناسب نیست. کلید نتیجه به کاربر/محدوده/برد/operationId وابسته است. pending پس از خرابی پردازش، نتیجه نامعلوم می‌دهد و مجوز اجرای دوباره نیست. برای بازیابی دامنه یا نگهداری در جدول موجود میزبان، قرارداد `Contracts\ModelOperationStore` را bind کنید. پاک‌کردن cache عملیات، تضمین جلوگیری از تکرار را از بین می‌برد.
